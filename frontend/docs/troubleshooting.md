# Troubleshooting

Legenda das marcas: [README](../README.md#legenda-de-evidências). Cada item traz o **sintoma**, a **causa** (confirmada ou provável) e **verificações/soluções**. Kubernetes está fora do escopo desta etapa.

Situação: ✅ ocorreu e foi resolvido/explicado · ⚠️ comportamento esperado do estado atual · 🔎 causa provável, não reproduzida · ⏳ pendente.

## Ambiente local

| ✅ `node: command not found` / `pnpm: command not found`                                                             | **Confirmada:** terminal sem o Node 26 no `PATH` (nvm não carregado). **[Testado]**                                                                                                                                                                                                                  | `nvm use` na raiz (lê `.nvmrc`). Confira `node -v` → `v26.12.1` e `pnpm -v` → `12.15.0`.                                                                                                                                                |

A advertência pode aparecer em logs antigos, mas não corresponde ao workspace atual. **[Arquivo]**                                                              | Confira os arquivos atuais do workspace em `frontend/`; detalhes da instalação Vercel em [vercel.md](vercel.md).                                                                                                                        |
| 🔎 `ERR_PNPM_OUTDATED_LOCKFILE` ao rodar `pnpm install --frozen-lockfile`                                            | **Relato:** ocorreu na configuração Vercel por divergência entre `package.json` e `pnpm-lock.yaml`.                                                                                                                                                                                                  | A correção relatada foi sincronizar com `pnpm install --lockfile-only` e validar com `pnpm install --frozen-lockfile`. Veja [vercel.md](vercel.md).                                                                                     |
| 🔎 `EADDRINUSE` / porta ocupada ao subir `pnpm dev`                                                                  | **Provável:** processo anterior (dev, Compose ou `docker run`) ainda usa 3000, 3001 ou 3002.                                                                                                                                                                                                         | `lsof -nP -iTCP:3000-3002 -sTCP:LISTEN`; encerre o processo pelo PID, ou `docker compose down`/`docker rm -f`. **[Testado]** o comando de listagem.                                                                                     |
| ⚠️ `pnpm start` ou `pnpm --filter <app> start` falha com `Missing script start` / `ERR_PNPM_RECURSIVE_RUN_NO_SCRIPT` | **Esperado:** as três apps não têm script `start`. Docker usa o servidor standalone; o deploy Vercel é configurado separadamente como descrito em [vercel.md](vercel.md). **[Arquivo]**                                                                                                          | Para ambiente local equivalente às imagens, use `docker compose up -d --build` ([docker-compose.md](docker-compose.md)) ou `docker run` ([docker.md](docker.md)). Para desenvolver: `pnpm dev`. Não há suporte a `next start`.          |
| ✅ `pnpm dev`: `/web` responde 502 e o log mostra `getaddrinfo ENOTFOUND web`                                        | **Confirmada:** `WEB_ORIGIN`/`ADMIN_ORIGIN` com nomes de serviço Docker (`http://web:3000`) no ambiente local; esses nomes só resolvem dentro da rede do Compose. **[Testado]**                                                                                                                      | No `apps/proxy/.env.local` (e no shell) use `http://localhost:3000` e `http://localhost:3001`; reinicie o dev server. Ver [environment.md](environment.md#por-que-os-endereços-internos-do-docker-não-servem-no-desenvolvimento-local). |
| ⚠️ `http://localhost:3000/` ou `:3001/` → 404                                                                        | **Confirmada:** `basePath`. **[Testado]**                                                                                                                                                                                                                                                            | Acesse `http://localhost:3000/web` e `http://localhost:3001/admin` (ou via proxy).                                                                                                                                                      |
| ✅ Mudei `.env` e o `pnpm dev` não refletiu                                                                          | **Confirmada:** o `next dev` lê `.env*` do diretório da app (`apps/proxy/.env.local`), não o `.env` da raiz, que serve só ao Compose. **[Testado]**                                                                                                                                                  | Edite `apps/proxy/.env.local` (valores de `localhost`) ou exporte as variáveis; reinicie o dev server. Ver [environment.md](environment.md).                                                                                            |
| 🔎 `pnpm build` falha ao buscar a fonte Roboto                                                                       | **Provável:** sem acesso à internet (`next/font/google` em `web`/`admin`). | ⚠️ `pnpm format:check` acusa `context/project-context.md` e `prompts/documentation-agent.md`                         | **Confirmada:** esses arquivos de insumo não estão no formato do Prettier. **[Testado]**                                                                                                                                                                                                             | Os documentos novos (`README.md`, `docs/*`) foram formatados com Prettier. Para os dois de insumo, decida se formata (`pnpm exec prettier --write <arquivo>`) ou os ignora.                                                             |
| 🔎 Importei algo de `@frontend/ui` e o TypeScript/Next não encontra                                                  | **Provável:** o símbolo não é exportado pelo ponto de entrada usado (`packages/ui/src/index.ts`, `theme/index.ts` ou `components/<Nome>/index.tsx`) ou o alvo de `exports` não tem extensão (o TypeScript acusa `TS2307`, mesmo que o bundler resolva) ou a app não tem a dependência `workspace:*`. | Exporte em `src/index.ts`; confirme `@frontend/ui` no `package.json` da app e rode `pnpm install`. Ex.: `tokens.ts` não é exportado hoje.                                                                                               |
| 🔎 Imports reprovados no lint                                                                                        | **Provável:** regra `simple-import-sort` (ordem react → next → @mui → @frontend → pacotes → relativos).                                                                                                                                                                                              | Ajuste a ordem; `pnpm exec eslint . --fix` **[A testar]**.                                                                                                                                                                              |

## Proxy

| Sintoma                                                                                                               | Causa                                                                                                                                                                          | Verificação / solução                                                                                                                                                                                                                                                                                          |
| --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ✅ `/web` (ou `/admin`) responde **502**, `{"error":"O serviço está temporariamente indisponível..."}` ou página HTML | **Confirmada:** o proxy não alcançou o destino (serviço parado, porta/nome errado). **[Testado]** ao parar o `web` (no Compose e no `docker run`); recuperou ao reiniciar.     | `docker compose ps`; `docker compose logs --tail 50 proxy` (procure `Erro ao encaminhar...`); confira `WEB_ORIGIN`/`ADMIN_ORIGIN`; teste a conexão a partir do proxy ([docker-compose.md](docker-compose.md#diagnosticar-comunicação-entre-contêineres)). Em `pnpm dev`, confirme que as 3 apps estão rodando. |
| ✅ **504**                                                                                                            | **Confirmada:** destino não respondeu em 10 s (`REQUEST_TIMEOUT_MS`). **[Testado]** com um servidor local que nunca responde: 504 em ≈10,03 s, `TimeoutError` no log do proxy. | Veja os logs do destino; o log do proxy mostra o erro.                                                                                                                                                                                                                                                         |
| ⚠️ O proxy retorna 500 "puro" (JSON ou corpo do destino) em vez da página amigável                                    | **Esperado:** 5xx do destino só vira página amigável em navegação HTML (`Accept: text/html`, sem `rsc`/prefetch e fora de `/_next/`).                                          | Compare `curl -i` com e sem `-H 'Accept: text/html'` ([proxy.md](proxy.md#erros-amigáveis)).                                                                                                                                                                                                                   |
| 🔎 Redirect leva ao host errado (por exemplo, para `localhost:3002` quando o acesso é por outro endereço)             | **Provável:** `PROXY_PUBLIC_ORIGIN` não corresponde ao endereço que o navegador usa; é ele que o proxy usa ao reescrever `Location` internos.                                  | Ajuste `PROXY_PUBLIC_ORIGIN` no proxy e recrie o serviço.                                                                                                                                                                                                                                                      |
| ⚠️ `proxy-redirect-test` "passa" sem o proxy reescrever nada                                                          | **Confirmada:** no Docker/Compose o `web` não recebe `PROXY_PUBLIC_ORIGIN` e a rota é estática (gerada no build com o padrão `http://localhost:3002`). **[Testado]**           | Veja a limitação e o teste alternativo em [proxy.md](proxy.md#limitação-importante-do-teste-de-redirect-interno-testado--inferência).                                                                                                                                                                          |
| ⚠️ `/foo` → 404 no proxy                                                                                              | **Esperado:** só `/`, `/web*` e `/admin*` existem. **[Testado]**                                                                                                               | —                                                                                                                                                                                                                                                                                                              |
| 🔎 Páginas do `web` sem CSS/imagens atrás do proxy                                                                    | **Provável:** requisição de assets fora de `/web/_next/...` ou `/web/<arquivo>` (o `basePath` deve prefixar tudo). Não reproduzido.                                            | Abra o DevTools → Network e veja se os assets usam o prefixo; `curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3002/web/next.svg` (esperado 200; **[Testado]** com o ambiente saudável).                                                                                                             |

## Docker e Compose

| Sintoma                                                                     | Causa                                                                                                                                                                                                                  | Verificação / solução                                                                                                                                |
| --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 🔎 `docker build` falha em `pnpm install --frozen-lockfile`                 | **Provável:** lockfile desatualizado em relação aos `package.json` copiados. Não reproduzido.                                                                                                                          | Atualize e versione o `pnpm-lock.yaml` e reconstrua.                                                                                                 |
| 🔎 `docker build` falha com "not found" ao copiar                           | **Provável:** build executado fora da raiz ou com `-f` errado; o contexto precisa ser a raiz (`.`).                                                                                                                    | Use exatamente `docker build -f apps/<app>/Dockerfile -t media-core-<app>:local .` na raiz.                                                          |
| ⚠️ Alterei o código, rebuildei, e o contêiner continua antigo               | **Esperado:** contêiner em execução usa a imagem de quando foi criado.                                                                                                                                                 | `docker compose up -d --build <serviço>` (**[Testado]**) ou `docker rm -f` + `docker run`.                                                           |
| ⚠️ `docker compose restart` mantém logs antigos de erro                     | **Confirmada:** os logs do contêiner persistem entre reinícios. **[Testado]**                                                                                                                                          | Use `--tail`/`--since`, ou recrie o contêiner (`docker compose up -d --force-recreate <serviço>` **[A testar]**).                                    |
| ⚠️ `curl http://localhost:3000/web` falha com o Compose ligado              | **Esperado:** `web` e `admin` usam `expose` e não publicam porta no host. **[Testado]**                                                                                                                                | Acesse por `http://localhost:3002/web` ou use `docker compose exec`.                                                                                 |
| ⚠️ O proxy não sobe imediatamente                                           | **Esperado:** `depends_on` com `service_healthy`; o proxy aguarda `web` e `admin` ficarem saudáveis (até `start_period` de 20 s + intervalos). **[Testado]**                                                           | `docker compose ps`; veja `docker compose logs web admin` se ficarem `unhealthy`.                                                                    |
| 🔎 Serviço `unhealthy`                                                      | **Provável:** o app não respondeu (ou respondeu 5xx) no caminho do health check (`/web`, `/admin`, `/`). Não reproduzido.                                                                                              | `docker inspect <contêiner> -f '{{.State.Health.Status}}'` (**[Testado]** → `healthy`; os estados de falha não foram reproduzidos); logs do serviço. |
| ✅ `The "X" variable is not set. Defaulting to a blank string.` no Compose  | **Confirmada:** `.env` ausente na raiz (ou sem a variável); o Compose usa string vazia. **[Testado]** O efeito no proxy (valor vazio não aciona o padrão do código) é **[Inferência]**.                                | `cp .env.example .env`; `docker compose config --quiet` (sem avisos). Ver [environment.md](environment.md).                                          |
| 🔎 Proxy no Compose acessa `localhost:3000` e falha                         | **Provável:** `WEB_ORIGIN`/`ADMIN_ORIGIN` do `.env` com `localhost` dentro do contêiner (aponta para o próprio proxy).                                                                                                 | Use os nomes de serviço no `.env` do Compose: `http://web:3000`, `http://admin:3001`.                                                                |
| ⚠️ `docker network ls` mostra `frontend-network` e `media-core_frontend-network` | **Esperado:** a rede do Compose recebe o prefixo do projeto; `compose.yaml` define atualmente `media-core`. A rede sem prefixo foi observada numa execução anterior. **[Histórico]** | Para identificar o projeto atual: `docker compose ls`; os nomes ainda precisam ser confirmados após a renomeação.                                     |
| 🔎 Porta `3002` em uso ao subir o Compose                                   | **Provável:** `pnpm dev` do proxy, outro `docker run` ou outro projeto Compose ocupando a porta.                                                                                                                       | `lsof -nP -iTCP:3002 -sTCP:LISTEN`; encerre o processo, ou `docker ps` para achar o contêiner.                                                       |

## Como coletar informações para pedir ajuda

```bash
node -v ; pnpm -v ; docker --version ; docker compose version
docker compose ps
docker compose logs --tail 100 proxy web admin
curl -i http://localhost:3002/web
```

Não cole o conteúdo de `.env` ou `apps/proxy/.env.local`.
